# 마이페이지와 작성자 프로필

로그인 후 사이드바의 **마이페이지** 또는 하단 프로필을 누르면 `/mypage`를 엽니다. 모임에 가입하지 않은 계정도 사용할 수 있습니다.

- 닉네임: 공백을 제외한 1~30자. 기존 글·댓글·자료·일정과 멤버 목록에도 현재 닉네임을 표시합니다.
- 프로필 사진: PNG/JPG, 최대 2MB, 원본 최대 4096×4096. 서버에서 실제 이미지 형식을 검사하고 중앙을 잘라 512×512 PNG로 저장합니다. 기본 이미지로 돌아갈 수도 있습니다.
- 계정 정보: 본인 이메일, 실제 계정 가입일, 참여 모임 수.
- 내 활동: 현재 참여 중인 모임의 커뮤니티 글과 등록 자료를 페이지별로 조회하며 항목을 누르면 해당 모임의 상세 화면으로 이동합니다.

## Supabase

현재 연결된 프로젝트에는 `supabase/migrations/20261008011928_member_profiles.sql` 변경을 적용했습니다. 기존 회원의 표시 이름을 보완하고, 프로필 사진 경로·수정 시각·활동 조회 인덱스와 비공개 `profile-avatars` 버킷을 생성합니다. 새 환경은 초기 스키마를 만든 뒤 이 migration을 적용해야 합니다. 기존 DB 설정과 서버의 `SUPABASE_SERVICE_ROLE_KEY`를 그대로 사용하므로 추가 키는 필요하지 않습니다.

프로필 테이블 및 사진 저장소는 클라이언트 직접 접근을 허용하지 않습니다. 서버는 JWT의 사용자 ID로 본인 프로필만 수정하고, 사진 조회는 본인 또는 해당 작성자와 모임을 공유하거나 해당 모임의 작성물을 볼 수 있는 회원에게 허용합니다. 이메일은 본인 `/me` 응답에만 포함됩니다. 사진 삭제/교체 시 이전 파일도 정리합니다.

## API와 검증

`GET/PATCH /api/v1/me`, `GET /api/v1/me/activity?type=posts|documents&page=0&size=20`, `POST/DELETE /api/v1/me/avatar`, `GET /api/v1/profiles/{id}/avatar`. 업로드는 multipart의 `file` 필드를 사용합니다. 브라우저는 쿠키 인증을 사용하는 `/api/proxy/`를 통해 호출합니다.

```sh
pnpm typecheck
pnpm build
pnpm test:profile
```

`test:profile`은 루트 `.env`를 읽고 실행 중인 프론트엔드·백엔드와 실제 Supabase를 검사합니다. 임시 계정 2개와 모임을 생성해 닉네임 반영, 글/댓글/자료/멤버 작성자, 내 활동, 사진 형식·크기 제한, 모임 권한, 사진 삭제를 확인한 후 삭제합니다. 기존 회원과 모임은 수정하지 않습니다. 기본 주소는 `http://localhost:3000`; 필요하면 `PROFILE_TEST_ORIGIN`으로 지정합니다.

백엔드 단위 테스트는 이미지 변환·위조 이미지 거부·다른 모임 사용자의 접근 거부를 추가 검증합니다. 브라우저의 실제 클릭 및 모바일 시각 검수는 별도 확인이 필요합니다.
