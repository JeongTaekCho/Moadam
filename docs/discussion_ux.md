# 커뮤니티·일정 상세와 댓글

커뮤니티 카드는 제목·본문 미리보기·작성자·빈 공간까지 하나의 클릭 영역입니다. 키보드 Tab과 Enter/Space로도 열 수 있으며 내부 버튼을 중첩하지 않습니다. 상세는 목록 이동/관리 버튼, 분류·제목·작성자·작성 시각, 본문, 댓글 카드로 구분합니다. 일정 상세에는 동일한 댓글 카드가 참석 응답 아래에 배치됩니다.

## 작성 흐름

`features/discussion/ui/discussion-section.tsx`가 공통 댓글 영역을 담당합니다. 댓글은 상세 화면에 항상 표시되는 에디터에서 작성합니다. 답글을 누르면 원댓글 아래에 대상 닉네임과 답글 에디터를 표시하며, 대댓글에 답하면 같은 원댓글의 답글로 등록합니다. 한 단계 답글 구조로 모바일 들여쓰기가 깊어지지 않게 합니다.

- 공백 입력은 등록 불가, 최대 5,000자. Enter는 줄바꿈, Ctrl/⌘ + Enter는 등록입니다. 한글 IME 조합 중 단축키는 실행하지 않습니다.
- 답글·수정 에디터는 열릴 때 포커스를 받으며 취소/Escape로 닫습니다. 일반 댓글의 초안은 답글 작업 중에도 유지됩니다.
- 요청 진행 중 중복 등록을 차단하고 성공 응답의 댓글·작성자 정보를 즉시 반영합니다. 실패 시 입력을 유지하고 에디터 안에 오류를 표시합니다.
- 삭제는 댓글 옆 인라인 확인 영역에서 진행합니다. 댓글은 삭제 안내로 바꾸며 기존 답글은 보존합니다.
- 작성자 또는 모임 관리자만 수정·삭제할 수 있습니다. 삭제된 댓글의 수정 및 새로운 답글은 서버에서 제한합니다.
- 댓글 조회만 실패해도 상세 본문은 유지되며 재시도를 제공합니다. 초기 댓글 조회는 간단한 스켈레톤을 사용합니다.
- 상세를 바꾸면 에디터 상태를 초기화합니다. 페이지 이탈·모임 변경 시 이전 조회를 취소하고 늦은 응답이 다른 상세에 반영되지 않게 합니다.

기존 댓글 모달, workspace의 중복 댓글 조회/상태, 사용하지 않는 CommentItem은 제거했습니다. 댓글 변경은 shared/api의 인증·모임 경계와 캐시 무효화를 따릅니다.

## API·DB

커뮤니티의 기존 `/api/v1/groups/{g}/posts/{p}/comments` GET/POST 및 `/{id}` PATCH/DELETE 계약을 유지하고 일정에도 `/groups/{g}/events/{id}/comments` 및 `/{commentId}`를 추가합니다. 생성 요청은 `body`와 선택적인 `parent_id`를 받습니다. 공통 CommentService가 모임 멤버십, 대상 자원, 부모 댓글의 같은 대상 여부, 작성자/관리자 권한을 검사합니다.

Comment 응답에 `event_id`, `parent_id`, `deleted`를 추가했습니다. 일정 댓글의 `post_id`는 null이며 커뮤니티 댓글의 `event_id`는 null입니다. 목록은 원댓글 작성순으로 묶고 원댓글을 먼저 반환합니다. 기존 페이지 제한 100개를 유지하며 더 보기로 추가 조회합니다. 삭제 안내도 대화 흐름을 위해 목록에 남으므로 전체 개수에 포함됩니다.

마이그레이션은 기존 comments 테이블에 컬럼을 추가합니다. 기존 댓글은 그대로 유지됩니다. XOR 대상 제약, 모임 범위 FK, 부모 FK, 자기 참조 방지, 부모 불변·동일 대상·한 단계 답글 검사 트리거, 조회 인덱스를 추가했습니다. 기존 RLS와 anon/authenticated 접근 차단을 유지하며 서버가 권한을 검사합니다. 트리거 함수는 SECURITY INVOKER이며 공개 역할에 실행 권한을 부여하지 않습니다.

## 배포 전 적용

현재 backend의 Flyway 기본값은 `FLYWAY_ENABLED=false`입니다. 새 댓글·답글 API를 사용하기 전에 Supabase SQL Editor에서 `supabase/migrations/20261012045229_threaded_comments.sql` 전체를 한 번 실행하고 backend/frontend를 함께 배포합니다. 기존 초기 migration을 다시 실행하지 않습니다. Flyway로 관리하는 별도 환경은 동일한 `V2__threaded_comments.sql` 복사본을 사용하며 두 관리 방식을 중복 적용하지 않습니다.

이 작업에서는 운영 DB에 SQL을 실행하지 않았습니다. 격리 PGlite에 V1/V2를 적용해 실제 SQL 조회·제약·답글 보존을 검증합니다. API 타입은 `make api-types`로 생성합니다.

## QA

- `pnpm test:db`: 초기 및 신규 SQL 적용, 대상/모임 격리, 잘못된 부모·대상의 중첩 댓글 거절, 원댓글 삭제 후 답글 보존, 일정 댓글, RLS.
- `mvn verify`: 댓글 서비스의 다른 대상 접근 거절, 권한, 삭제·중첩 부모 제한, 일정 답글 등록, 기존 전체 테스트.
- `pnpm test:discussion-ui`: 1440/390px 격리 API fixture로 카드 전체/키보드 이동, 인라인 등록·실패 후 초안 유지·단축키·취소·대댓글의 부모 바인딩·수정·삭제·초안 격리·가로 넘침 확인.
- `pnpm test:performance`, `pnpm test:events-ui`: 기존 캐시·세션·일정 생성/수정/참석 회귀 검사.

운영 계정·실제 DB로 댓글 등록/삭제하는 live smoke는 실행하지 않습니다.

## 상세 주소와 새로고침

커뮤니티는 `/community/{글ID}?group={모임ID}`, 일정은 `/events/{일정ID}?group={모임ID}` 주소를 사용합니다. Next의 `[section]/[id]` 동적 라우트는 커뮤니티/일정과 UUID 형식을 검사하고 비공개 metadata를 유지합니다. 워크스페이스 레이아웃은 유지하며 실제 브라우저 주소를 외부 store로 구독합니다. 새로고침·직접 접속·브라우저 뒤로/앞으로 이동 시 상세 API를 조회해 화면을 복원합니다. 일정은 상세 정보와 참석 응답을 병렬 조회합니다. 상세 진입에서는 전체 목록 조회를 생략합니다.

목록/상세 전환 시 이전 조회 결과를 무효화하며, 삭제·수정 이후 재조회는 실행 시점의 주소를 기준으로 합니다. 상세를 여는 중에는 해당 상세의 준비 상태에 맞춰 스켈레톤을 표시합니다. 목록으로 돌아가기·삭제는 목록 주소로 복귀하고 모임 query를 유지합니다. 마이페이지에서 내 커뮤니티 글을 여는 동작에도 상세 주소를 적용합니다.

2026-10-12 대댓글 400 진단: 설정된 DB에서 `parent_id`, `event_id`, `deleted` 컬럼 적용을 읽기 전용으로 확인했습니다. 실행 중이던 로컬 및 Render의 OpenAPI는 CommentInput에 `body`만 선언하고 일정 댓글 경로도 없었습니다. 기존 서버의 unknown JSON field 검증에 의해 parent_id 요청이 거절되는 버전 불일치입니다. 로컬 서버를 최신 코드로 재시작해 `parent_id`·일정 댓글 경로가 노출되는 것을 확인했습니다. Render는 최신 백엔드 커밋으로 재배포해야 합니다. 마이그레이션을 중복 실행할 필요는 없습니다. 실제 회원 댓글을 생성하는 운영 smoke나 운영 배포는 수행하지 않았습니다.
