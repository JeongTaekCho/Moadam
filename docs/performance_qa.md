# 서비스 최적화 및 QA 보고서

검증 날짜: 2026-10-08. 프론트엔드 운영용 빌드와 격리한 브라우저/API 환경에서 검증했습니다. 운영 배포 및 실제 사용자 계정으로 로그인·메일·파일 업로드를 실행한 결과와 구분합니다.

## 캐시 정책

브라우저 탭 메모리에만 저장합니다. localStorage, 디스크, 공용 서버/CDN 데이터 캐시는 사용하지 않습니다. 인증 BFF의 HTTP `no-store`는 유지하며, 클라이언트에서 이미 수신한 데이터만 재사용합니다.

- 일반 모임/게시글/멤버 목록 등: 최대 30초.
- 자료 조회: 최대 10초. 처리 상태가 변할 수 있어 더 짧게 유지합니다.
- 내 활동/AI 대화 목록: 최대 15초.
- `me` 로그인 확인, 참석 응답, 채팅 메시지, 다운로드/업로드 URL 등: 결과 캐시 없음. 같은 시점의 동일 요청 합치기만 적용합니다.
- 경로의 쿼리 문자열을 포함한 전체 URL이 키입니다. 모임과 페이지 번호가 다른 데이터는 섞이지 않습니다.
- 최대 100개 응답을 보관하며 오래된 항목부터 제거합니다. 반환 데이터는 복사해 화면에서 변경해도 원본 캐시가 오염되지 않도록 합니다.
- POST/PATCH/PUT/DELETE 성공, 사진 업로드 성공, AI 답변 완료 시 조회 캐시를 비웁니다.
- 로그인 성공·로그아웃·401 응답 시 세션 캐시를 제거하고 이전 요청을 취소합니다.
- 모임 변경 시 이전 모임의 진행 중인 요청을 취소합니다. 캐시에서 반환할 때도 세션/모임/호출자의 취소 상태를 검사합니다.
- 홈·커뮤니티·자료·일정·멤버 화면으로 탭 포커스가 복귀할 때 최소 30초 간격으로 최신 목록을 조회합니다. 숨겨진 탭과 저장/AI 작업 중에는 재조회하지 않습니다.
- 요청을 공유하는 한 호출자가 취소해도 다른 호출자의 요청은 계속됩니다. 모든 호출자가 취소하면 실제 조회도 중단합니다.
- 실패 응답과 취소한 응답은 캐시하지 않습니다. ‘다시 시도’는 캐시를 비운 뒤 요청합니다.

인증 확인 후 모임 목록을 요청하는 순서는 유지합니다. 만료된 로그인에서 여러 보호 API를 동시에 호출하지 않도록 하는 실제 요구사항입니다. 권한은 서버에서 계속 검사합니다. 다른 사용자가 수정한 내용은 위 유효기간 내 잠시 이전 값이 보일 수 있으며 화면 재방문/복귀 시 다시 확인합니다.

## QA

### 자동 검증

- `pnpm build`: 운영 빌드 및 TypeScript 검사.
- `pnpm test:cache`: 중복 요청, 만료, 최대 항목 수, 복사본 격리, 변경 후 갱신, 개별 취소/전체 취소, 실패 후 재시도, 로그아웃/401 초기화, 모임 격리, 인증/서명 URL 비캐싱 검사.
- `pnpm test:performance`: Playwright로 운영 빌드를 실행하고 보호 API를 지연하는 격리 fixture로 UI와 API 호출을 함께 검사. 실제 서버에 데이터 쓰기 없음.
- `pnpm test:oauth`: Google PKCE 시작/콜백/취소/실패/쿠키 및 이메일 인증 대기·중복 가입·비밀번호 검증.
- `pnpm test:chat-stream`: 한글 UTF-8 분할, 중단·오류, BFF가 완료 전에 스트림 전달, 취소 전달. 새 캐시 의존성도 테스트 빌드에 포함하도록 보완.
- `pnpm test:db`: PostgreSQL/pgvector 마이그레이션 및 권한·격리 검사 13개, PGlite와 Auth/Storage fixture 사용.
- 백엔드 Maven 검사 21개: 기존 보안/권한/DTO/스트리밍/프로필 계약과 실제 HTTP gzip 압축 검사.
- RAG unittest 17개: 검색 모임 격리, 타인 세션 차단, 청킹, 근거 부족, 공급자 오류, 한글/이모지 스트리밍 등.

### 브라우저 검증 흐름

1. 비로그인 8개 앱 경로: 보호 API 요청 0회.
2. 지연된 로그인 확인: 데스크톱 스켈레톤 표시.
3. 자료/커뮤니티 왕복: 캐시 유효기간 안의 재방문에 추가 GET 없음.
4. 게시글 수정: 새 제목으로 갱신, 목록 재조회.
5. 멤버/초대: 관리자 요청이 병렬 시작.
6. 마이페이지 재방문: 활동 조회 캐시 재사용.
7. 대화 빠른 전환: 마지막 선택한 대화 유지, 늦은 이전 응답 무시.
8. 503 오류 후 재시도: 정상 자료 목록으로 복구.
9. 모임 전환: 새 모임 경로 조회 및 이전 모임 콘텐츠 제거.
10. 로그아웃: 인증 화면 표시, 이후 보호 API 호출 없음.
11. 재로그인: 이전 캐시 없이 프로필과 모임 자료 새 조회.
12. 게시글 삭제: 목록 갱신 및 삭제한 글 제거.
13. 세션 만료: `me` 401 이후 다른 보호 API 요청 없음.
14. 390px 모바일: 가로 넘침 없음, 스켈레톤 표시, reduced-motion에서 애니메이션 없음.

브라우저 QA 전체 통과. 최종 실행에서 캐시 재방문은 74ms였으며 추가 API 요청이 없었습니다(앞선 실행 94ms). fixture 지연과 로컬 머신 기준으로, 운영 사용자 지연시간을 대표하지 않습니다.
백엔드 실제 HTTP 검사에서 OpenAPI JSON은 32,767 → 2,768 bytes로 압축됐습니다(약 91.6% 감소). 응답 내용과 압축 해제 결과도 검사했습니다. 일반 API의 크기 절감률은 데이터에 따라 다릅니다.

브라우저 캡처: `/tmp/moadam-performance-qa/boot-desktop.png`, `/tmp/moadam-performance-qa/boot-mobile.png`.
재현: 프론트엔드에서 `pnpm exec playwright install chromium`, `pnpm build`, `pnpm test:cache`, `pnpm test:performance` 순서로 실행합니다. 브라우저 QA는 3112 포트를 사용합니다.

## 점검 결과와 운영 확인 범위

- 작성자 프로필 조회는 기존 배치 조회를 유지해 목록마다 작성자 수만큼 조회하는 N+1 방식으로 변경하지 않았습니다.
- DB에는 모임·게시글·댓글·일정·문서·대화·작성자 활동용 인덱스가 존재합니다. 실제 DB 실행 계획/운영 부하 측정 없이 인덱스나 풀 크기를 임의로 변경하지 않았습니다.
- AI 화면의 프레임 단위 스트리밍 및 기존 메시지 memo 렌더링을 유지했습니다. RAG의 검색/공급자 스트리밍 로직은 회귀 검사했으며 알고리즘이나 모델을 변경하지 않았습니다.
- 이 작업은 로컬 변경입니다. 프론트엔드 Vercel과 백엔드 Render 재배포가 필요합니다.
- 운영 Supabase/Google 로그인·SMTP 전달·실제 업로드·OpenAI 응답시간·Render 콜드 스타트는 이번 fixture QA로 검증한 항목이 아닙니다. 배포 후 운영 계정에서 확인해야 합니다.
