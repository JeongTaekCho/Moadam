# 일정 캘린더와 날짜 입력

## 화면

월 이동은 버튼·월 제목을 같은 행 중앙에 정렬합니다. 캘린더는 react-calendar 6.0.1의 월/일 그리드를 사용하며, 한국 시간의 날짜를 브라우저 로컬 civil date로 전달해 해외 시간대에서도 날짜가 바뀌지 않도록 합니다. 일요일부터 6주를 표시하고 날짜 클릭은 그날의 일정 목록을 엽니다. 띠 클릭은 일정 상세를 엽니다.

달력의 일정 띠는 일자 타일 안에 중첩 버튼을 넣지 않고 별도 overlay grid에 렌더링합니다. 시작일~마지막 포함일을 일자 칸 너비만큼 연결하고 주/월 경계에서는 나눠 이어 표시합니다. 겹친 기간은 일관된 lane에 배치하며 최대 3줄을 보입니다. 넘치는 일정은 `+n개`로 알리고 날짜 아래 목록에서 전체를 확인할 수 있습니다.

선택한 달의 42칸 기간을 기준으로 기존 API의 `from` 필터를 사용합니다. 시작 시각으로 정렬된 응답을 페이지별로 모아 표시 범위가 끝나면 조회를 중단합니다. 첫 100개를 넘어도 해당 월의 일정을 누락하지 않으며, 월 변경/화면 이탈 시 이전 조회 결과를 적용하지 않습니다. 별도의 목록 페이지 이동은 제공하지 않습니다.

## 입력과 저장

일정 생성 폼은 날짜 선택을 먼저 배치하고 그다음 제목·장소·설명을 받습니다.

- 기본값: 같은 날짜 체크, 시간 추가 미체크. ‘일정 만들기’는 날짜를 직접 선택하고 ‘이 날짜에 추가’는 선택한 날짜를 미리 채웁니다.
- 같은 날짜를 체크하면 종료일을 시작일에 연결하고 종료일 피커를 비활성화합니다.
- 시간 추가를 체크할 때만 시작/종료 시간 피커를 활성화합니다. 신규 또는 시간 없는 일정의 기본 시간은 09:00~10:00이고, 시간 있는 일정 수정은 기존 시간을 복원합니다.
- 시작일보다 빠른 종료일, 같은 날 시작보다 늦지 않은 종료 시간, 잘못된 날짜/시간은 저장하지 않습니다.
- 입력 피커는 기존 공통 DatePicker/TimePicker를 사용하며 직접 타이핑하지 않습니다.

시간 없는 일정은 KST 시작일 00:00부터 종료일 다음 날 00:00까지의 반개구간으로 저장합니다. 화면의 종료일은 마지막 포함일입니다. 시작/종료가 정확한 KST 자정인 기존 일정도 같은 규칙으로 하루 종일 표시합니다. 시간 있는 일정이 자정에 끝나면 다음 날을 띠에 포함하지 않습니다. API는 기존 starts_at/ends_at UTC 계약을 유지하며 별도 checkbox 값을 전송하지 않습니다.

상세는 날짜 타일·제목·등록자, 기간·장소, 안내, 참석 응답으로 구성합니다. 참석 상태는 aria-pressed로 표시하며 수정 저장 후 상세와 달력에 최신 응답을 반영합니다.

## 검증

- `node scripts/event-calendar-smoke.mjs`: 하루/여러 날, 잘못된 입력, 자정 종료, 주/월/연도 경계, 겹친 lane/overflow.
- `node scripts/event-calendar-ui-smoke.mjs`: 운영 빌드에서 fixture API로 1440px/KST와 390px/LA 시간대를 검증. 정렬·42개 타일·주 경계 띠·생성 체크박스·UTC 저장·상세·참석·수정·105개 일정 페이지 조회를 확인합니다.
- `pnpm check`, `pnpm build`, `pnpm test:performance`, `make conventions`를 추가 실행합니다.

브라우저 QA는 3113 포트를 사용하며 캡처는 `/tmp/moadam-calendar-qa/`에 저장합니다. 실제 운영 데이터에 쓰기 작업을 하지 않습니다.

라이브러리 안내: [react-calendar 6.0.1](https://github.com/wojtekmaj/react-calendar/tree/v6.0.1/packages/react-calendar).

## 과거 날짜와 참석 응답 제한

한국 시간 기준 오늘 이전 날짜는 시작/종료 피커에서 선택할 수 없습니다. 종료일은 시작일 이후여야 합니다. 과거 날짜는 달력에서 기록을 확인할 수 있지만 ‘이 날짜에 추가’는 비활성화됩니다. 생성·수정 요청에서도 과거 시작일은 서버에서 차단합니다.

시작일이 오늘 이전인 일정은 참석/미정/불참 응답을 변경할 수 없습니다. 조회와 기존 응답 현황은 유지합니다. 버튼 비활성화·안내 문구·클릭 시 재검사 외에도 서버에서 HTTP 409로 차단하고 저장하지 않습니다. 오늘 시작한 일정은 시작 시간이 이미 지났더라도 응답할 수 있습니다. 날짜 경계는 UTC가 아닌 Asia/Seoul입니다.

EventDatePolicyTest는 한국 자정 직전/직후와 오늘 허용, 과거 요청 저장 0회, 과거 등록 차단을 검사합니다. 브라우저 QA에서도 어제 피커 비활성화/오늘 활성화와 과거 일정의 응답 버튼 3개 비활성화를 KST/LA 환경에서 확인합니다.

## 날짜에서 바로 일정 만들기

오늘(한국 시간)부터 이후 날짜 칸에 포인터를 올리면 `새 일정` 버튼이 나타납니다. 버튼 클릭 시 선택 날짜와 표시 월을 맞추고, 일정 모달의 시작일·종료일을 해당 날짜로 채웁니다. 이전 날짜는 조회할 수 있지만 생성 버튼은 표시하지 않습니다.

키보드로 날짜 또는 생성 버튼에 포커스를 이동해 사용할 수 있습니다. 터치 환경에서는 선택 날짜에 버튼을 표시합니다. React Calendar의 날짜 버튼 내부에 다른 버튼을 중첩하지 않고 별도 그리드에 생성 버튼을 배치해 일정 띠·날짜 선택을 유지합니다. reduced motion에서는 버튼 전환 애니메이션을 제거합니다. 브라우저 QA는 오늘/과거 제한, 날짜 바인딩, 키보드·모바일·인접 월 동작을 검사합니다.
