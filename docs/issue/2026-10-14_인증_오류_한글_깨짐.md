# 인증 오류 응답의 한글 깨짐

- 작성일: 2026-10-14 (한국 시간)
- 상태: 코드 수정 완료 / 운영 확인 대기
- 영향 범위: Spring Security 인증 실패 응답, 이를 전달받는 BFF 및 API 클라이언트

## 어떤 이슈였나

운영 `/api/v1/me`, `/api/v1/groups`를 인증 없이 조회하면 401 응답의 `message`가 `???? ?????`로 반환됐다. 보호 API 접근 차단은 정상이나 로그인 안내 문구가 손상됐다.

## 원인과 확인 근거

운영 응답의 Content-Type은 `application/json;charset=ISO-8859-1`이었다. `SecurityConfig`의 인증 실패 처리기가 JSON을 직접 `getWriter()`로 쓰면서 응답 인코딩을 지정하지 않았다. JSON 변환기를 사용하는 일반 API와 달리 서블릿 Writer의 기본 인코딩이 적용돼 한글이 물음표로 변환됐다.

기존 실제 HTTP 통합 테스트는 401 상태와 영문 오류 코드만 검사했다. UTF-8 및 한국어 메시지 검증을 추가한 뒤 수정 전 `expected: UTF-8 but was: ISO-8859-1` 실패를 재현했다.

## 어떻게 수정했나

- `SecurityConfig`에서 Writer를 얻기 전에 UTF-8을 명시했다.
- 기존 `ContractTest`에서 실제 HTTP 응답의 charset과 JSON `message`가 `로그인이 필요합니다`인지 검증한다.
- 상태 코드, 오류 코드, requestId 및 인증 정책은 유지했다.

## 검증 결과

- 수정 전 실제 HTTP 통합 검사에서 charset 불일치를 재현했다.
- 수정 후 백엔드 전체 `mvn verify`: 52개 테스트, Spotless 검사와 JAR 패키징 통과. 실제 HTTP 통합 검사에서 UTF-8 헤더와 정확한 한국어 메시지를 확인했다.

## 운영 적용과 남은 작업

운영 배포는 수행하지 않았다. 백엔드 배포 후 인증 없는 요청의 401 응답 헤더와 한국어 메시지를 다시 확인해야 한다. SQL 변경은 필요 없다.
