# 운영 빌드와 FK 인덱스 보완

- 작성일: 2026-10-14 (한국 시간)
- 상태: 코드·SQL 작성 및 격리 검증 완료 / 운영 적용 대기
- 영향 범위: 프론트 production 빌드, DB 참조 컬럼 인덱스

## 어떤 이슈였나

기본 Turbopack production 빌드가 로컬 PostCSS 하위 프로세스 포트 바인딩에서 `Operation not permitted`로 실패했다. 동일 소스의 Webpack 빌드는 통과했고 Vercel의 기존 배포도 READY였다. 서비스 코드 컴파일 실패와 로컬 실행 환경 문제를 구분했다.

Supabase 성능 advisor는 참조 측 인덱스가 없는 외래 키 6개를 보고했다. 기존 복합 인덱스는 첫 컬럼이 다르거나 중간 컬럼이 있어 해당 사용자·멤버 참조를 충분히 덮지 못했다. 현재 작은 운영 데이터에서 지연을 측정한 것은 아니며 데이터 증가 시 조회·FK 검사와 관련 정리 작업에 대비한 보완이다.

## 어떻게 수정했나

- `pnpm build`를 설치된 Next.js CLI가 지원하는 `next build --webpack`으로 명시해 검증·CI의 production 빌드 경로를 통일했다. Turbopack 자체의 내부 버그를 고쳤다는 의미는 아니다. 개발 서버는 기존 명령을 유지한다.
- Supabase CLI 2.120.0의 `migration new`로 `20261014040550_foreign_key_indexes.sql`을 생성하고 Flyway `V6__foreign_key_indexes.sql`과 같은 내용을 저장했다.
- chat_sessions.user_id, comments.author_id, event_attendees.(group_id,user_id), event_attendees.user_id, events.author_id, group_invites.created_by에 `IF NOT EXISTS` 인덱스를 추가한다.
- 테이블 데이터·RLS·권한·확장 스키마는 변경하지 않는다. 기존 마이그레이션도 수정하지 않았다.
- 마이그레이션 복사본 검사와 PGlite 검사를 보강했다. 대상 외래 키 6개가 유효한 비부분 인덱스의 선두 컬럼으로 모두 덮이는지, SQL 반복 실행이 가능한지, 기존 클라이언트 접근 차단이 유지되는지 확인한다.

## 검증 결과

- 변경된 기본 `pnpm build`: 성공.
- `pnpm check`, AI 오류 UI·성능·스트리밍 검사: 통과.
- `pnpm test:db`: 기존 DB 격리·토큰·자료 작업 검사 및 새 인덱스 6개 검사 통과.
- Ruff 및 마이그레이션/의존성/저장소 규칙 검사: 통과.

## 운영 적용과 남은 작업

- 코드 배포와 원격 DB SQL 실행은 수행하지 않았다.
- SQL Editor를 사용하는 경우 `supabase/migrations/20261014040550_foreign_key_indexes.sql`을 실행한다. 현재 소규모 데이터 기준의 일반 인덱스 생성이며, 큰 테이블에서 적용한다면 쓰기 잠금 시간을 별도로 평가해야 한다.
- 유출 비밀번호 보호와 vector 확장 스키마 경고는 서비스 장애가 아니다. 플랜·Auth 정책 및 기존 vector 타입 의존성 확인이 필요한 별도 운영 설정 항목으로 유지한다. RLS 정책 없음 알림을 없애기 위한 공개 접근 정책이나 미사용 인덱스 삭제는 필요하지 않다.
