# 이슈 수정 기록

이슈를 수정할 때 어떤 문제가 있었고 어떻게 해결했는지 한국어로 기록합니다. 코드 변경과 함께 기록을 작성하고, 후속 검증이나 운영 적용 결과가 나오면 같은 문서를 갱신합니다.

## 파일 이름

- 경로: `docs/issue/YYYY-MM-DD_이슈명.md`
- 날짜: 처음 수정 기록을 작성한 날짜, 한국 시간(Asia/Seoul) 기준.
- 이슈명: 문제를 알아볼 수 있는 짧은 한국어 이름. 공백 대신 밑줄을 사용합니다.
- 예시: [2026-10-13*배포환경*모아AI\_응답실패.md](2026-10-13_배포환경_모아AI_응답실패.md)
- 같은 이슈는 기존 문서에 날짜별 후속 내용을 추가합니다. 과거 관찰 결과와 현재 상태를 구분합니다.

## 작성 기준

증상과 영향, 확인된 원인, 수정 내용과 관련 파일, 실제 실행한 검증, 운영 적용 여부와 남은 작업을 작성합니다. 확인되지 않은 원인은 추정이라고 명시하고, 격리·mock 테스트 통과를 운영 정상화로 표현하지 않습니다. 비밀번호·토큰·인증 링크·실제 회원 데이터는 기록하지 않습니다.

상태는 `조사 중`, `코드 수정 완료 / 운영 확인 대기`, `해결 완료`처럼 현재 상황을 드러내도록 적습니다. 운영 이슈는 필요한 배포와 실제 동작 확인까지 마친 경우에만 해결 완료로 표시합니다. 운영 적용이 필요 없는 이슈는 해당 사실과 검증 결과를 적습니다.

## 기본 양식

```markdown
# 이슈 제목

- 작성일: YYYY-MM-DD (한국 시간)
- 상태: 현재 상태
- 영향 범위: 관련 화면·API·서비스

## 어떤 이슈였나

발생 상황, 사용자에게 보인 증상, 재현 방법을 작성합니다.

## 원인과 확인 근거

확인된 원인과 근거를 작성합니다. 아직 확인되지 않은 내용은 별도로 구분합니다.

## 어떻게 수정했나

수정한 동작과 이유, 관련 파일이나 문서 링크를 작성합니다.

## 검증 결과

실행한 검사와 결과, 검증 환경 및 확인하지 못한 범위를 작성합니다.

## 운영 적용과 남은 작업

배포·설정 적용 여부와 추가로 확인할 내용을 작성합니다.

## 후속 기록

후속 작업이 있을 때 날짜와 변경 내용, 검증 결과를 추가합니다.
```
