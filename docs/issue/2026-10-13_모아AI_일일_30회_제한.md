# 사용자별 모아AI 일일 30회 제한

- 작성일: 2026-10-13 (한국 시간)
- 상태: 구현·격리 검증 완료 / 운영 마이그레이션·배포 대기
- 영향 범위: 모아AI 질문 API, 입력창 주변 UI, 사용자별 호출 횟수 저장

## 어떤 이슈였나

모아AI 질문에 사용자별 일일 한도가 없어 반복 호출을 제한하지 못했고, 사용자가 입력창에서 남은 횟수를 확인할 수 없었습니다. 사용자별 하루 30회 제한과 남은 횟수 UI를 요청받아 추가했습니다.

## 원인과 확인 근거

기존 질문 API에는 사용자별 호출 횟수 저장·검사 단계가 없었습니다. 성공한 대화 메시지만 세면 실패·중지·대화 삭제로 횟수를 우회할 수 있으므로, 별도의 사용자·날짜별 카운터를 추가했습니다.

## 어떻게 수정했나

- 모든 모임·대화를 합쳐 인증된 사용자당 하루 30회로 제한합니다. 한국 시간(Asia/Seoul) 자정부터 새로운 날짜의 한도를 사용합니다.
- 모임 권한과 개인 대화 소유권을 확인한 뒤 DB의 `INSERT ... ON CONFLICT ... WHERE ... RETURNING` 한 문장으로 횟수를 차감합니다. 31번째 요청은 모델/RAG 호출 전 HTTP 429로 거절합니다. [PostgreSQL 원자적 UPSERT 규칙](https://www.postgresql.org/docs/current/sql-insert.html)을 적용했습니다.
- 서버가 접수한 질문은 답변 실패·사용자 중지 여부와 관계없이 1회입니다. 권한 오류·입력 검증 실패·한도 초과 요청은 차감하지 않습니다. 차감은 별도 트랜잭션으로 커밋해 답변 저장 실패로 되돌아가지 않도록 했습니다.
- 스트리밍·일반 질문 API에 같은 한도를 적용합니다. 스트리밍 시작 시 `usage` 이벤트로 차감 후 횟수를 전달합니다.
- `GET /api/v1/me/ai-usage`는 현재 로그인한 사용자의 `limit`, `used`, `remaining`, `resets_at`을 반환합니다. 프론트 횟수 조회는 캐시하지 않으며 AI 모달 열기·요청 종료·창 포커스 복귀·초기화 시점에 갱신합니다.
- 입력창 위에 작은 모아 아이콘과 남은 횟수 배지, 초기화 안내를 표시합니다. 횟수 확인 실패 시 재확인 버튼을 제공하고 한도 소진 시 전송을 막습니다. 이미 접수한 마지막 답변은 계속 표시하거나 중지할 수 있습니다.
- 카운터 테이블은 RLS를 활성화하고 `anon`·`authenticated`의 직접 조회·수정 권한을 제거했습니다. 서버 JDBC만 횟수를 관리합니다. [Supabase RLS 문서](https://supabase.com/docs/guides/database/postgres/row-level-security)를 확인했습니다.

관련 구현: [AiUsageService](../../backend/src/main/java/com/moadam/ai/service/AiUsageService.java), [AiUsageRepository](../../backend/src/main/java/com/moadam/ai/repository/AiUsageRepository.java), [AiService](../../backend/src/main/java/com/moadam/ai/service/AiService.java), [모아AI UI](../../frontend/src/_pages/workspace/ui/chat-view.tsx).

## 검증 결과

- 백엔드 Maven: 34개 테스트 통과. 두 질문 API의 한도 초과 차단, 권한 오류 시 미차감, 한국 시간 초기화 응답, 실패 스트림의 횟수 전달을 확인했습니다.
- 격리 PostgreSQL(PGlite): 실제 JDBC 차감 SQL로 40개 대기 요청 중 30개만 접수되는지, 사용자별 분리, 전날 한도와 오늘 한도의 분리, 클라이언트 역할의 직접 접근 차단을 확인했습니다. PGlite 검사는 큐로 처리되며 운영 다중 연결 부하 검사는 아닙니다.
- 프론트 `pnpm check`, `pnpm build`, 스트리밍 QA 통과.
- 1440px·390px 브라우저 QA: 실패 후 횟수 갱신과 재시도, 30번째 질문 완료 후 전송 차단, 외부 횟수 변경 후 포커스 복귀 시 갱신을 확인했습니다. 모바일 레이아웃도 스크린샷으로 확인했습니다.
- OpenAPI와 생성 TypeScript 타입을 갱신했습니다.

## 운영 적용과 남은 작업

운영 DB 변경과 배포는 수행하지 않았습니다. 적용 순서는 다음과 같습니다.

1. Supabase SQL Editor에서 [신규 마이그레이션](../../supabase/migrations/20261013045254_ai_daily_usage.sql)을 적용합니다. 기존 마이그레이션을 다시 실행하지 않습니다.
2. Spring 백엔드와 Vercel 프론트엔드의 수정 코드를 배포합니다.
3. 로그인 후 모아AI 모달에서 횟수 조회와 질문 시 차감이 정상인지 확인합니다.

Flyway를 사용하는 환경에서는 동일한 [V3 마이그레이션](../../backend/src/main/resources/db/migration/V3__ai_daily_usage.sql)을 사용합니다. 같은 DB에 Supabase SQL 적용과 Flyway 적용을 중복 수행하지 않습니다. 현재 기본 설정은 `FLYWAY_ENABLED=false`입니다.

이 한도 작업은 기존 [운영 AI 응답 실패 이슈](2026-10-13_배포환경_모아AI_응답실패.md)의 RAG 연결 복구와 별개입니다. 해당 이슈의 운영 확인 상태는 그대로 유지합니다.
