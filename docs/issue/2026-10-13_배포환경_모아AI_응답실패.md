# 배포 환경에서 모아AI 답변이 나오지 않는 이슈

- 작성일: 2026-10-13 (한국 시간)
- 상태: 코드 보완·격리 검증 완료 / 운영 복구 확인 대기
- 영향 범위: 모아AI 질문 모달, Spring AI 스트리밍 API, Python RAG 연결
- 운영 환경: 프론트엔드 Vercel, 백엔드 Render

## 어떤 이슈였나

`https://moadam.vercel.app/`에서 모아AI에 질문해도 답변이 나오지 않았습니다. 실패 안내가 AI 모달 밖에 표시되어 사용자가 실패 이유를 확인하기 어려웠습니다.

임시 테스트 계정과 자료가 없는 테스트 모임을 만들어 Vercel 경유 요청과 Spring 직접 요청을 비교했습니다. 두 요청 모두 HTTP 200과 NDJSON 스트림을 반환했지만, `status`의 검색 단계 직후 오류 이벤트로 종료되었습니다. 답변 조각인 `delta`와 완료 이벤트인 `done`은 오지 않았고 완료 답변도 저장되지 않았습니다. 테스트 후 임시 모임과 계정은 삭제했습니다.

## 원인과 확인 근거

### 확인한 내용

- Vercel 경유·Spring 직접 요청에서 동일한 실패가 재현되었습니다. Vercel 프록시는 상태와 오류 이벤트를 전달하고 있었습니다.
- Spring 운영 OpenAPI에 현재 스트리밍 경로가 존재했습니다. 이전 API만 배포된 상태는 아니었습니다.
- 실패 지점은 Spring에서 검색을 시작한 뒤 RAG를 호출하는 구간으로 좁혀졌습니다. 자료가 없는 모임의 경로는 모델 API를 호출하지 않으므로, 이 재현만으로 모델 API 키 오류라고 판단할 수 없습니다.
- 프론트엔드의 오류 표시가 모달 밖에 있어 실패 안내가 잘 보이지 않는 UI 문제가 있었습니다.

### 아직 확인하지 못한 내용

Render의 실제 `RAG_URL`, 내부 인증 토큰 일치 여부, Python RAG 서비스 배포 상태와 로그는 확인하지 못했습니다. RAG 주소 오류, 서비스 미배포, 내부 인증 실패, 잘못된 API 경로는 점검 대상이며 확정 원인은 아닙니다.

## 어떻게 수정했나

| 변경 영역             | 수정 내용                                                                                                                                                   |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Spring RAG 클라이언트 | 주소의 공백과 끝 슬래시를 정리하고 연결 실패·시간 초과·인증 실패·경로 오류·용량 제한·상위 서비스 오류를 구분했습니다.                                       |
| AI 스트리밍 서비스    | 오류 이벤트에 안전한 오류 코드와 안내 메시지를 포함했습니다. 서버 로그에 오류 분류를 남기되 인증정보·질문·상위 응답 본문은 기록하지 않도록 했습니다.        |
| 모아AI 모달           | 입력창 위에 오류 안내를 표시하고, 실패 시 질문을 유지해 재시도할 수 있도록 했습니다.                                                                        |
| Vercel 프록시         | Node.js 런타임과 최대 실행 시간을 명시하고 기존 스트림 전달·취소 처리를 유지했습니다.                                                                       |
| Python RAG            | 비밀정보를 반환하지 않는 공개 `/healthz`를 추가하고 Docker가 Render의 `PORT`를 사용하도록 수정했습니다. 기존 상세 상태·검색·색인 API의 인증은 유지했습니다. |
| 배포·점검 도구        | RAG 서비스용 `render.yaml`과 연결·준비 상태를 읽기 전용으로 검사하는 스크립트를 추가했습니다.                                                               |
| 회귀 검증             | 통신 오류 분류, 스트리밍 실패, 모달 오류 표시와 재시도를 검사하고 프론트 QA 명령 및 CI에 연결했습니다.                                                      |

관련 구현은 [RagClient.java](../../backend/src/main/java/com/moadam/ai/client/RagClient.java), [AiService.java](../../backend/src/main/java/com/moadam/ai/service/AiService.java), [chat-view.tsx](../../frontend/src/_pages/workspace/ui/chat-view.tsx), [RAG 진입점](../../rag/app.py)에 있습니다. 배포·설정 절차와 오류 코드 설명은 [운영 복구 가이드](../ai_production_troubleshooting.md)를 참고합니다.

## 검증 결과

아래 결과는 로컬·격리 환경의 코드 검증입니다. 수정 코드가 운영에 배포되어 정상 답변을 반환한다는 의미는 아닙니다.

- 백엔드 Maven 검증: 31개 테스트 통과. RAG 통신 오류와 실패한 답변의 저장 방지를 확인했습니다.
- Python RAG: 17개 테스트 및 Ruff 검사 통과. 공개 상태 경로와 인증이 필요한 기존 경로를 확인했습니다.
- 프론트엔드: `pnpm check`, `pnpm build` 통과.
- 스트리밍 QA: UTF-8 처리, 중간 종료·오류, 취소 및 프록시의 점진적 전달 확인.
- 모달 QA: 1440px·390px에서 오류 표시, 질문 유지, 재시도 성공, 로딩 종료 확인.
- 기존 성능·OAuth QA, `make conventions`, `git diff --check` 통과.
- Render Blueprint 공식 스키마 검증 및 읽기 전용 점검 스크립트의 정상·인증 실패·준비 상태 실패 시나리오 통과.

## 운영 적용과 남은 작업

이 작업에서 운영 배포나 Render 설정 변경은 수행하지 않았습니다. 다음 항목을 확인한 뒤 운영 복구 완료 여부를 갱신해야 합니다.

- [ ] Python RAG 서비스의 배포 여부와 실제 주소 확인.
- [ ] Spring의 `RAG_URL` 및 두 서비스의 `RAG_INTERNAL_TOKEN` 일치 여부 확인.
- [ ] 필요한 수정 코드 배포와 RAG 환경변수 적용.
- [ ] [연결 점검 스크립트](../../scripts/check-ai-deployment.mjs)로 상태·준비 상태 확인. 이 검사는 실제 모델 응답 성공까지 보장하지 않습니다.
- [ ] 운영에서 질문 후 `delta`·`done`, 답변 표시와 저장을 확인. 실제 자료를 참조하는 답변도 검증.
