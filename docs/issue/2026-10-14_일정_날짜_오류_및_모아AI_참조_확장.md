# 일정 날짜 오류 안내와 모아AI 일정·공지 참조

- 작성일: 2026-10-14 (한국 시간)
- 상태: 코드·검증 및 로컬 적용 완료 / 운영 배포 대기
- 영향 범위: 일정 편집 폼, 일정 API 오류, RAG 검색·인용, 모아AI 출처 이동

## 증상과 원인

지난 날짜에 시작한 일정을 수정하면 시작일 정책 때문에 저장할 수 없었지만, 일반적인 오류 문구로 무엇을 고쳐야 하는지 알기 어려웠다. 프론트는 유효하지 않은 기간의 타임스탬프를 비워 전달했다. 날짜 입력 칸의 grid 정렬과 최소 너비 때문에 오류 텍스트가 생길 때 입력 칸 크기가 변할 수 있었다.

모아AI는 업로드 문서 조각만 검색해서 DB에 등록한 일정과 커뮤니티 공지를 답변 근거로 쓰지 못했다.

## 수정 내용

- 시작일 정책은 한국 시간의 오늘 날짜 기준으로 유지한다. 프론트 필드 오류와 서버 응답을 **“시작일이 오늘보다 전입니다. 시작일을 오늘 또는 이후 날짜로 수정해 주세요.”**로 통일했다.
- 시작일 아래에 오류를 표시하고 시작일 입력을 `aria-invalid`로 연결했다. 수정하면 오류를 지운다. 타임스탬프가 비어도 기간 오류를 먼저 검사한다.
- 서버는 HTTP 400과 `EVENT_START_BEFORE_TODAY`를 반환한다. 일반 오류 처리에서 이 문구를 보존하되, 다른 내부 예외 내용을 외부에 노출하도록 범위를 넓히지 않았다.
- 날짜 grid는 `minmax(0, 1fr)`와 상단 정렬을 사용하고 오류 텍스트를 줄바꿈한다. 날짜 칸의 오류가 달력 버튼이나 반대편 날짜 칸을 늘리지 않는다.
- RAG가 멤버십·개인 세션을 검사한 다음 같은 모임의 일정과 `kind='notice'` 공지만 현재 DB에서 조회한다. 일정의 제목·한국 시간 시작/종료·장소·설명, 공지의 제목·내용을 모델 근거로 제공한다. 일반 게시글과 댓글은 이번 범위에 포함하지 않는다.
- 일정은 관련성·진행 중/예정 순으로 최대 50개 후보, 공지는 관련성·수정일 순으로 최대 40개 후보를 조회한다. 모델에는 일정 최대 8개·공지 최대 6개, 총 본문 9,000자 이내로 제공한다. 많은 자료의 전체 목록을 확인했다고 주장하지 않는다.
- 자료가 없어도 일정·공지를 참고할 수 있고 기존 문서 검색·일반 질문·이전 대화·토큰 정산을 유지한다. 공지와 특정 일정의 관계가 명시되지 않으면 해당 일정의 규칙으로 연결하지 않도록 지침을 추가했다.
- 답변 후 모임 권한과 원문의 존재·수정 시각·공지 종류를 다시 검사한다. 생성 중 수정·삭제된 원문은 답변 근거로 반환하지 않는다.
- 인용에 `source_type`·`source_id`를 추가하고 기존 문서 인용과의 호환성을 유지한다. 일정/공지 출처를 누르면 모아AI 창을 닫고 해당 원문 화면을 연다. OpenAPI와 생성 TypeScript 계약을 갱신했다.

## 검증

- Spring `mvn verify`: 날짜 정책·정확한 오류 응답·API 계약 등 **52개 테스트 통과**.
- RAG Ruff 및 unittest: **52개 통과**. 문서 없는 일정·공지 답변, 스트리밍 인용, 다른 모임 분리, 수정·삭제 후 인용 거절을 추가 검사했다.
- 프론트 `pnpm check`: 포맷·린트·타입 검사 통과.
- 프론트 `next build --webpack`: 운영 빌드 통과. 기본 Turbopack 빌드는 내부 프로세스의 포트 바인딩 `Operation not permitted` 오류로 실패해 별도로 구분한다.
- 일정 브라우저 QA: **1440px/390px 통과**. 과거 시작일의 정확한 문구와 `aria-invalid`, 입력/버튼 높이, 가로 넘침 없음, 날짜 수정 후 오류 해제, 일정 저장·수정·참석·페이지 조회를 확인했다. 캡처는 `/tmp/moadam-calendar-qa/past-date-error-*.png`이다.
- 모아AI 화면 QA 및 성능 QA 통과. 실제 모델 결과를 재생해 **일정·공지·혼합 답변과 원문 이동을 1440px/390px에서 확인**했다.
- 실제 OpenAI: 합성 일정·공지와 메모리 DB fixture로 세 질문 유형을 검증했다. 마지막 결과는 1,772 / 1,724 / 1,807토큰(합계 5,303토큰)이며, 필요한 출처와 내용이 반환됐다. 원본 결과는 `/tmp/moadam-group-context-live-report.json`이다. 실회원의 내용을 모델에 전송한 검증은 아니다.
- 연결된 실제 DB에는 읽기 전용 조회로 새로운 SQL이 실행되는 것을 확인했다. 무작위의 비어 있는 모임 범위를 사용해 회원 데이터를 읽거나 변경하지 않았다.
- 저장소 구조·마이그레이션 복사본·`git diff --check` 통과.

## 적용

기존 `events`·`posts` 테이블과 JSON 인용 컬럼을 사용하므로 **추가 SQL이나 마이그레이션은 필요 없다**. 새 Python 모듈은 RAG Dockerfile에도 포함했다. 운영에는 백엔드·RAG·프론트를 함께 배포해야 하며 운영 배포는 수행하지 않았다.

최신 백엔드 실행 파일로 백엔드·RAG·프론트를 모두 재시작했다. 새 PID는 각각 80373·80372·80374이며 로컬 세 서비스 HTTP 200 응답과 최신 API 계약을 확인했다. 로컬 접속 주소는 `http://localhost:3000`이다.
