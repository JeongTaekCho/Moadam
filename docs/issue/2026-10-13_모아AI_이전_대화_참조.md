# 모아AI 이전 대화 참조와 답변 가독성 개선

- 작성일: 2026-10-13 (한국 시간)
- 상태: 코드 수정 완료 / 운영 확인 대기
- 영향 범위: RAG 일반/스트리밍 검색·답변, 답변 문단 구성

## 어떤 이슈였나

대화는 저장하고 있었지만 검색 임베딩과 답변 모델에는 현재 질문과 문서 발췌만 전달했다. “그건 언제야?”, “장소는?”, “더 쉽게 설명해줘”처럼 앞선 대상을 가리키는 질문은 맥락 없이 검색되어 이어지는 대화가 어려웠다. 답변의 줄바꿈과 문단 구성을 추가로 개선해 달라는 요청도 있었다.

## 원인과 확인 근거

`rag/app.py`의 `prepare_query()`는 현재 질문만 임베딩했고 `generation_payload()`에는 대화 내역이 없었다. DB의 `chat_messages`와 `messages_session(group_id,session_id,sequence)` 인덱스는 이미 존재하여 추가 테이블이나 공개 API 변경 없이 서버에서 제한된 대화를 읽을 수 있었다.

## 어떻게 수정했나

- 멤버십과 개인 세션 소유권을 확인한 후 같은 모임·세션·사용자의 최근 12개 메시지를 `sequence DESC`로 조회한다. DB 조회 단계부터 메시지당 1,200자로 제한하고 총 6,000자까지만 시간순으로 전달한다.
- 근거 없는 이전 assistant 답변은 제외하며 대화는 클라이언트 입력을 받지 않는 요청별 private attribute로 보관한다. 다른 세션과 공유하거나 공용 캐시에 저장하지 않는다.
- 지시어·재설명 요청·짧은 후속 질문을 감지한 경우에만 검색 질문 보완을 한 번 추가한다. 명확한 새 질문과 첫 질문은 기존의 한 번 임베딩 경로를 유지한다.
- 보완 모델 출력은 200토큰·1,000자로 제한한다. HTTP timeout 8초/연결 timeout 3초를 설정하고, 오류·잘린 응답·잘못된 형식은 재시도 없이 최근 주제를 제한된 길이로 붙이는 검색으로 전환한다. 원래 질문을 검색 입력에 유지한다.
- 대화 조회 후 DB 연결을 닫고 모델 보완·임베딩을 호출한다. 검색 직전 및 답변 완료 시 멤버십·세션 소유권을 다시 검사한다. 스트리밍 준비는 기존 threadpool을 유지한다.
- 대화와 이전 답변은 의도 파악용으로만 쓰고 현재 발췌에서 사실과 인용을 확인하도록 지시한다. 기존 허용 문서·현재 버전·인용 검증은 유지한다.
- 핵심 답을 먼저 제시하고 보통 2~3문장마다 문단을 나누며, 주제 전환·목록 앞뒤에는 빈 줄을 넣도록 생성 지침을 강화했다. 자료 없음 등 고정 안내도 상황 설명과 다음 동작 사이에 빈 줄을 넣는다.
- 이전 작업의 스트리밍 마크다운 표시·코드 공백 보존 개선을 유지한다. 완료 답변을 임의로 재가공하지 않아 작성 중 표시와 저장 답변의 일치를 유지한다.
- `rag/README.md`, `docs/feature_readme.md`, `frontend/STREAMING_AI.md`에 실제 흐름과 제한을 반영했다.
- Ruff에 `app`을 로컬 모듈로 명시해 루트와 RAG 디렉터리에서 실행할 때 import 정렬 결과가 달라지는 기존 검사 문제를 정리했다.

OpenAI의 [대화 상태 문서](https://developers.openai.com/api/docs/guides/conversation-state)와 [JSON 출력 문서](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)를 확인했다. 기존 Chat Completions와 JSON 응답 계약을 유지하고 보완 결과를 서버에서 검증한다.

## 검증 결과

- RAG `ruff check`, `ruff format --check`: 통과.
- RAG unittest 29개: 통과. 대화 조회 범위·길이·순서, 요청별 격리와 외부 대화 주입 차단, 새 주제 보완 생략, 후속 질문 보완/실패 대체, 네트워크 호출 중 DB 연결 해제, 접근 권한 재검사, 과거 인용 재사용 거부를 검증했다.
- 스트리밍 provider fixture로 최근 대화 전달과 완료 전 delta 출력, 문단·목록 줄바꿈의 delta/최종 답변 일치를 확인했다.
- 프론트 `pnpm check`, `pnpm test:ai-errors`, `pnpm test:chat-stream`: 통과. 모바일 390px/데스크톱 1440px의 마크다운 표시 검사를 포함한다.
- `make conventions`: 통과.
- 실제 운영 DB와 유료 모델 호출은 수행하지 않았다. fixture 검사는 실제 모델 답변 품질이나 속도 향상을 측정한 결과가 아니다.

## 운영 적용과 남은 작업

운영 배포는 수행하지 않았다. RAG 변경을 배포한 뒤 실제 연속 질문의 검색 품질과 답변 문단 구성을 확인해야 한다. 보완 여부는 한국어·영어의 패턴 기반 판별이며 모든 표현을 포괄하지 않는다. 오래된 대화는 길이 제한으로 제외될 수 있다. 후속 질문은 추가 모델 호출 비용과 대기 시간이 발생할 수 있다. 사실 답변에는 현재 검색 가능한 문서 근거가 필요하며 문서가 없거나 삭제된 경우 과거 대화만으로 사실을 확정하지 않는다.
