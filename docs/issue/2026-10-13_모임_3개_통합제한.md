# 사용자별 모임 3개 제한과 통합 AI 횟수 확인

- 작성일: 2026-10-13 (한국 시간)
- 상태: 구현·로컬 실제 API 검증 완료 / 운영 배포 대기
- 영향 범위: 모임 생성·초대 참여, 한도 안내 모달, 사용자별 AI 질문 횟수

## 어떤 이슈였나

사용자가 만드는 모임과 참여하는 모임에 합산 한도가 없었습니다. 두 동작을 합쳐 최대 3개로 제한하고, 초과 시 에러 모달을 표시하도록 요청받았습니다. AI 질문도 모든 모임을 합쳐 사용자당 하루 30회인지 재확인했습니다.

## 원인과 확인 근거

기존 `GroupService.createGroup()`과 `join()`에는 계정별 전체 멤버십 수 검사와 동시 요청 보호가 없었습니다. 개수 확인만 추가하면 여러 탭·서버에서 동시에 요청할 때 한도를 넘을 수 있으므로, 두 진입점이 같은 사용자 잠금을 사용하도록 했습니다.

AI 횟수는 이미 `ai_daily_usage`의 `(user_id, usage_date)`를 기준으로 저장하며 `group_id`가 없습니다. 기존 통합 30회 정책을 유지하고 실제 API로 교차 모임 차감을 확인했습니다.

## 어떻게 수정했나

- 소유자·관리자·멤버를 구분하지 않고 현재 소속된 모임을 모두 합산합니다. 3개 이상이면 새 모임 생성과 새 모임 참여를 HTTP 409, `GROUP_LIMIT_REACHED`로 거절합니다.
- 두 진입점에서 사용자 UUID에 대응하는 PostgreSQL 트랜잭션 advisory lock을 획득한 뒤 개수를 조회합니다. READ COMMITTED를 명시해 앞 요청의 커밋 결과를 다음 요청이 보도록 했습니다. 잠금은 트랜잭션 종료 시 해제됩니다. [PostgreSQL 잠금 문서](https://www.postgresql.org/docs/current/explicit-locking.html)를 참고했습니다.
- 초과 요청은 모임·멤버십·감사 기록을 생성하지 않고 초대 코드를 사용 처리하지 않습니다.
- 이미 소속된 모임의 유효한 초대 코드를 입력하면 기존 모임을 반환하며 추가 슬롯이나 초대 코드를 소모하지 않습니다.
- 기존 모임 탈퇴·삭제로 소속 모임이 3개 미만이 되면 다시 생성·참여할 수 있습니다. 이미 3개를 넘는 계정의 기존 모임을 강제로 삭제하지 않습니다.
- 프론트에서 전용 코드를 인식해 편집 모달을 닫고, 공통 Dialog로 최대 3개 안내와 탈퇴·삭제 후 재시도 안내를 표시합니다.
- AI는 모든 모임·대화를 합쳐 하루 30회, 한국 시간 자정 초기화 정책을 유지합니다. 접수된 요청은 답변 실패·중지 시에도 차감됩니다.

관련 파일: [GroupService](../../backend/src/main/java/com/moadam/group/service/GroupService.java), [GroupRepository](../../backend/src/main/java/com/moadam/group/repository/GroupRepository.java), [에러 계약](../../backend/src/main/java/com/moadam/group/exception/GroupLimitException.java), [워크스페이스 모달](../../frontend/src/_pages/workspace/ui/workspace-page.tsx).

## 검증 결과

- 백엔드 Maven: 41개 테스트 통과. 생성·참여 공통 한도, 3번째 허용, 잠금→개수 확인 순서, 초대 미소모, 기존 참여자 재진입, 한국어 에러 계약을 검증했습니다.
- 프론트 `pnpm check`, `pnpm build` 통과.
- 1440px·390px 브라우저 QA: 생성·참여 실패 시 안내 모달, 닫기·확인, 편집 모달 종료, AI 통합 횟수 표시와 전송 차단 확인. 모바일 화면을 시각 검토했습니다.
- 기존 성능 QA 통과: 인증·캐시·모임 전환·대화 경합·모바일 동작.
- 실제 로컬 Spring API + 연결 DB 검증: 임시 계정으로 생성 4건을 동시에 보내 정확히 3건 성공·1건 한도 오류를 확인했습니다. 4번째 모임 참여 거절 시 초대가 미사용으로 남고, 기존 모임 삭제 후 참여에 성공했습니다. 이미 참여한 모임의 다른 초대도 소비되지 않았습니다.
- 다른 모임 두 곳에서 AI 스트림을 요청해 한 사용자의 횟수가 30→29→28로 감소하고 다른 사용자는 30을 유지함을 확인했습니다. 새 빈 모임만 사용해 모델 호출·자료 색인은 하지 않았습니다.
- 실제 검증 후 임시 모임·Auth 계정을 삭제했습니다. 명시적으로 실행하는 [live QA 스크립트](../../scripts/group-limits-live-smoke.mjs)는 기본 테스트에 포함하지 않습니다.

## 운영 적용과 남은 작업

이번 모임 제한에는 새 DB 마이그레이션이 없습니다. 로컬 백엔드는 최신 빌드로 재시작했습니다. 운영 백엔드·프론트엔드 배포는 수행하지 않았으며, 배포 후 두 서비스의 에러 계약이 함께 적용됐는지 확인해야 합니다.

추가 운영 위험과 권장 조치는 [배포·사용자 이용 점검 보고서](../service_release_review_2026-10-13.md)에 정리했습니다.
