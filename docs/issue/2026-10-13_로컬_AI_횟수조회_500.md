# 로컬 모아AI 횟수 조회의 HTTP 500 오류

- 작성일: 2026-10-13 (한국 시간)
- 상태: 로컬 복구 완료 / 예외 처리 보완 코드 운영 배포 대기
- 영향 범위: 로컬 모아AI 횟수 조회, 존재하지 않는 API의 오류 응답

## 어떤 이슈였나

일일 질문 한도 기능을 추가한 뒤 로컬에서 `GET /api/v1/me/ai-usage`가 HTTP 500을 반환했습니다. 사용자에게 표시된 requestId는 `5c8949d6-8720-494b-bb1a-308624816ae6`입니다.

## 원인과 확인 근거

해당 requestId의 백엔드 로그에서 `NoResourceFoundException: No static resource api/v1/me/ai-usage.`를 확인했습니다. 실행 중인 백엔드는 신규 API가 등록되기 전의 프로세스였고, 프론트엔드만 새 API를 호출하고 있었습니다.

기존 공통 예외 처리가 Spring의 `NoResourceFoundException`을 일반 예외로 분류해, 존재하지 않는 경로를 404 대신 500으로 반환했습니다. 연결 DB를 읽기 전용으로 확인한 결과 `public.ai_daily_usage` 테이블은 이미 존재했습니다. 이번 요청 실패의 원인은 테이블 누락이 아닙니다.

## 어떻게 수정했나

- 기존 로컬 백엔드 프로세스를 종료하고 현재 소스를 빌드한 백엔드를 다시 실행했습니다. 프론트엔드와 RAG 프로세스는 유지했습니다.
- [공통 예외 처리](../../backend/src/main/java/com/moadam/common/exception/GlobalExceptionHandler.java)가 Spring `ErrorResponse`의 HTTP 상태를 보존하도록 수정했습니다. 존재하지 않는 경로는 `HTTP_404`와 기존 requestId 형식으로 반환합니다.
- [회귀 테스트](../../backend/src/test/java/com/moadam/common/exception/GlobalExceptionHandlerTest.java)를 추가해 정적 리소스·핸들러 미존재 예외가 모두 404로 처리되는지 확인했습니다.
- 임시 로컬 실행 스크립트의 Maven 경로를 현재 설치 위치로 갱신했습니다.

## 검증 결과

- 백엔드 `spotless:apply verify`: 35개 테스트 통과.
- 재시작한 로컬 백엔드 OpenAPI에 `/api/v1/me/ai-usage` 경로가 등록된 것을 확인했습니다.
- 로컬 프론트엔드 로그에서 재시작 후 `GET /api/proxy/me/ai-usage 200`을 확인했습니다. 백엔드의 DB 연결도 정상 완료됐습니다.
- 연결 DB의 테이블 존재 여부만 조회했습니다. 원격 DB 수정이나 운영 배포는 수행하지 않았습니다.

## 운영 적용과 남은 작업

로컬 서버는 최신 코드로 실행 중입니다. Java 소스 변경 후 기존 `spring-boot:run` 프로세스가 자동으로 갱신되는 것은 아니므로 새 API를 추가했을 때 백엔드 재시작이 필요합니다.

운영 환경에서 예외 처리 보완을 사용하려면 수정된 백엔드를 배포해야 합니다. 운영 일일 한도 기능의 적용 여부와 기존 RAG 연결 이슈는 각각의 기록을 따릅니다.
